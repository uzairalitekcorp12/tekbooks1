# TekBooks complete beginner setup

Follow this guide from top to bottom. You do not need to understand AWS, MongoDB, Vercel, or Expo before starting.

TekBooks uses:

- MongoDB Atlas for accounts and bookkeeping records;
- a private Amazon S3 bucket for profile pictures, logos, attachments, invoice PDFs, and report files;
- Resend for signup, password-reset, device-change, and approval emails;
- Vercel for the public backend API;
- Expo EAS to create the installable Android APK.

Local development detects the currently active home/company Wi-Fi whenever `npm run dev` starts. The installed APK uses the permanent HTTPS Vercel address, so it works from any future Wi-Fi or mobile data.

## Important secret rule

Never paste real MongoDB passwords, complete Resend keys, AWS secret keys, JWT secrets, or admin keys into this guide, GitHub, the APK, screenshots, or public chat.

The Resend value shown in chat should be rotated if it was a real active key. A real Resend line has no trailing semicolon:

```dotenv
RESEND_API_KEY=re_your_complete_key
```

The Atlas example still contains `<db_password>`, so it is not ready until that placeholder is replaced. In the real `.env` file, do not include `<`, `>`, backslashes, or a trailing semicolon.

## Step 1: Install the project

Install Node.js 22 and Git. Open PowerShell in the main TekBooks folder and run:

```powershell
npm run setup
```

Atlas-backed development does not require local MongoDB or Docker.

## Step 2: Finish MongoDB Atlas

You already created the Atlas user and copied a URI. Complete these checks.

### 2.1 Check the database user

1. Sign in at <https://cloud.mongodb.com/>.
2. Open the `TekBooks` project.
3. Open **Security → Database Access**.
4. Open the `tekbooks_app` user.
5. Give it `readWrite` access to the `tekbooks` database.
6. Add another `readWrite` permission for `tekbooks_dev`.
7. Save.

Using `readWriteAnyDatabase` also works and is easier, but the two specific permissions are safer.

### 2.2 Allow Vercel and changing Wi-Fi addresses

1. Open **Security → Network Access**.
2. Select **Add IP Address**.
3. Select **Allow access from anywhere**, or enter `0.0.0.0/0`.
4. Add a comment such as `TekBooks Vercel and development`.
5. Confirm.

Atlas accepts database connections only from its IP access list. `0.0.0.0/0` is needed for this simple Vercel Hobby/changing-Wi-Fi setup, so use a long unique database password and never expose the URI. Official reference: <https://www.mongodb.com/docs/atlas/security/ip-access-list/>.

### 2.3 Finish the connection string

The copied value resembles:

```text
mongodb+srv://tekbooks_app:<db_password>@YOUR_CLUSTER.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
```

Replace `<db_password>` with the password created under **Database Access**.

Correct shape:

```text
mongodb+srv://tekbooks_app:ACTUAL_PASSWORD@YOUR_CLUSTER.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
```

If the password contains `@`, `:`, `/`, `?`, `#`, `[`, `]`, or `%`, those characters must be URL-encoded. The easiest beginner option is to reset the Atlas database-user password to a long random value using letters, numbers, `_`, and `-`, then copy it exactly.

Save the completed URI privately as `MONGODB_URI`. Do not put a backslash before `_`, and do not add quotes or a semicolon.

TekBooks uses the same free cluster with separate database names:

- local: `MONGODB_DB_NAME=tekbooks_dev`;
- deployed: `MONGODB_DB_NAME=tekbooks`.

## Step 3: Finish Resend

You already created an API key. Complete the correct option below.

### Option A: First private test

Use:

```dotenv
RESEND_FROM=TekBooks <onboarding@resend.dev>
RESEND_TEST_MODE=true
RESEND_TEST_RECIPIENT=YOUR_RESEND_ACCOUNT_EMAIL
```

This option is allowed on Vercel. The API, Atlas, S3, PDF/report features, and APK work normally, but email signup, verification, password reset, and device-change codes work only for `RESEND_TEST_RECIPIENT`. TekBooks rejects other signup email addresses with a clear test-mode message before creating an unusable account.

Use the same recipient in `npm run system:check`. This is a private testing deployment, not public customer email delivery.

### Option B: Real users

1. Sign in at <https://resend.com/>.
2. Open **Domains → Add Domain**.
3. Enter a company subdomain such as `mail.yourcompany.com`.
4. Open the company's DNS provider.
5. Add the exact SPF and DKIM records shown by Resend. Add its recommended DMARC record too.
6. Wait for Resend to show **Verified**.
7. Open **API Keys → Create API Key**.
8. Name it `tekbooks-production` and give it sending access.
9. Copy it once and save it privately.

Use:

```dotenv
RESEND_API_KEY=re_your_complete_key
RESEND_FROM=TekBooks <no-reply@mail.yourcompany.com>
RESEND_TEST_MODE=false
RESEND_TEST_RECIPIENT=
```

Changing from Option A to Option B requires only these Vercel environment-variable changes and a backend redeploy. The APK does not need rebuilding while its Vercel API URL stays the same.

Official references: <https://resend.com/docs/dashboard/api-keys/introduction> and <https://resend.com/docs/dashboard/domains/introduction>.

If the key previously pasted into chat was real, delete it in Resend and create a new one before continuing.

## Step 5: Create the local backend environment automatically

After you have the Atlas URI, Resend values, and four S3 values, run from the main TekBooks folder:

```powershell
npm run configure:local
```

The wizard asks for values in this exact order:

1. completed Atlas `MONGODB_URI`;
2. database name—press Enter to use `tekbooks_dev`;
3. `S3_REGION`;
4. `S3_BUCKET`;
5. `S3_ACCESS_KEY_ID`;
6. `S3_SECRET_ACCESS_KEY`;
7. `RESEND_API_KEY`;
8. `RESEND_FROM`.

Secret inputs are hidden. If `backend/.env` already exists, answer `y` to create a backup and replace it.

The wizard writes the real values only to ignored `backend/.env` and generates unique local JWT, media-signing, and admin secrets. It does not put secrets in GitHub or the mobile app.

For reference, the resulting private file has this shape:

```dotenv
NODE_ENV=development
APP_BASE_URL=http://localhost:4000
MONGODB_URI=mongodb+srv://...
MONGODB_DB_NAME=tekbooks_dev
JWT_SECRET=generated-automatically
MEDIA_SIGNING_SECRET=generated-automatically
ADMIN_API_KEY=generated-automatically
RESEND_API_KEY=re_...
RESEND_FROM=TekBooks <onboarding@resend.dev>
STORAGE_DRIVER=s3
S3_REGION=ap-south-1
S3_BUCKET=your-exact-bucket
S3_ACCESS_KEY_ID=your-dedicated-key-ID
S3_SECRET_ACCESS_KEY=your-dedicated-secret
```

Do not manually put real values in `backend/.env.example`; that file is a safe tracked reference only.

## Step 8: Put the backend on private GitHub

The backend folder can be deployed by itself.

1. Create a **private** GitHub repository named something like `tekbooks-api`.
2. Put the **contents** of the local `backend` folder at the root of that repository.
3. Before pushing, confirm the repository does not contain `.env`, `.env.backup-*`, `node_modules`, `dist`, `uploads`, or `.vercel`.
4. Push the other backend files, including `src`, `package.json`, `package-lock.json`, `tsconfig.json`, `vercel.json`, `.env.example`, `vercel-env.example.txt`, and `infra`. Do not add a legacy `functions` rule to `vercel.json`; the included file safely pins the framework to Express.

`backend/.gitignore` is already configured to block the secret/local files.

If you instead push the entire TekBooks repository, select `backend` as the Vercel Root Directory. If the GitHub repository contains only backend contents, use `.` as Root Directory.

## Step 9: Create Vercel and deploy the backend

1. Create an account at <https://vercel.com/signup> using GitHub.
2. Select **Add New → Project**.
3. Import the private backend repository.
4. Choose a stable project name such as `tekbooks-api-company`.
5. Set Root Directory according to Step 8.
6. Set Framework Preset to **Express**. The tracked `backend/vercel.json` also pins this setting so future deployments cannot be treated as an empty static project.
7. Select Node.js 22.
8. Leave Build Command and Output Directory unset; Vercel handles the Express TypeScript entry point. Keep Install Command at its default.
9. Open the project's **Environment Variables** section and choose **Production**.

Generate three different production security values from the main TekBooks folder:

```powershell
npm run secrets:production
```

Copy the three displayed values into a password manager. Do not run the command again until you have pasted them, because every run creates different values.

Add these variables to Vercel Production one by one:

| Name | What to paste |
|---|---|
| `NODE_ENV` | `production` |
| `APP_BASE_URL` | `https://YOUR-PROJECT-NAME.vercel.app` |
| `MONGODB_URI` | completed Atlas connection string |
| `MONGODB_DB_NAME` | `tekbooks` |
| `LOGIN_USERNAME` | internal login, for example `admin@tekbooks` |
| `LOGIN_NOTIFICATION_EMAIL` | real inbox for that login; in test mode use the Resend account email |
| `JWT_SECRET` | first generated project secret |
| `MEDIA_SIGNING_SECRET` | second generated project secret |
| `ADMIN_API_KEY` | third generated project secret |
| `RESEND_API_KEY` | complete production `re_...` key, without semicolon |
| `RESEND_FROM` | for now: `TekBooks <onboarding@resend.dev>` |
| `RESEND_TEST_MODE` | for now: `true` |
| `RESEND_TEST_RECIPIENT` | the Google/email address used to create your Resend account |
| `STORAGE_DRIVER` | `s3` |
| `S3_REGION` | first value supplied by your sir |
| `S3_BUCKET` | second value supplied by your sir |
| `S3_ACCESS_KEY_ID` | third value supplied by your sir |
| `S3_SECRET_ACCESS_KEY` | fourth value supplied by your sir |

Use [backend/vercel-env.example.txt](./backend/vercel-env.example.txt) as a name checklist only. Never edit that tracked file with real values.

Mark the MongoDB URI, generated secrets, Resend key, Resend test recipient, and AWS key values **Sensitive** in Vercel. Configure only Production for the first simple deployment; do not give untrusted Preview deployments access to production data.

When you later verify a Resend domain, change `RESEND_FROM` to your domain sender, change `RESEND_TEST_MODE=false`, clear `RESEND_TEST_RECIPIENT`, and redeploy the backend.

Select **Deploy**. When deployment finishes, copy the exact production address shown by Vercel.

Open these in a browser:

```text
https://YOUR-PROJECT.vercel.app/health
https://YOUR-PROJECT.vercel.app/ready
```

`/health` should show `"ok": true`. `/ready` should show both database and storage ready.

If the actual Vercel address differs from `APP_BASE_URL`, correct `APP_BASE_URL` under Vercel Environment Variables and redeploy.

Vercel Git deployments and environment-variable references: <https://vercel.com/docs/deployments/git> and <https://vercel.com/docs/environment-variables>.

## Step 11: Create the Expo project and APK

1. Create an account at <https://expo.dev/signup>.
2. Return to the complete TekBooks repository.
3. Run:

```powershell
Set-Location mobile
npx eas-cli login
npx eas-cli init
```

4. Check the public mobile values tracked in `mobile/eas.json` and `mobile/.env.example`:

```powershell
npm run mobile:env
Set-Location mobile
npx expo config --type public
```

Only the public API URL and the two public LAN/Metro flags belong in Expo. Never put MongoDB, Resend, S3, JWT, media-signing, or admin secrets into an `EXPO_PUBLIC_` variable.

`mobile/eas.json` already disables LAN/Metro discovery in installed builds. A build guard rejects localhost, emulator, private Wi-Fi, non-HTTPS, and URLs missing `/api`.

5. Return to the main repository and create an installable APK:

```powershell
Set-Location ..
npm run build:apk
```

The Expo Free queue may take time. When it finishes, open the EAS build URL on the Android phone, download the APK, allow installation from that browser/file manager, and install it.

TekBooks 1.0.11 includes a new native Android attachment opener. You must install a fresh APK; updating only the JavaScript bundle is not sufficient.

For Google Play later, build the AAB:

```powershell
npm run build:aab
```

The preview profile creates an APK for direct installation. The production profile creates an AAB for Google Play. Official Expo references: <https://docs.expo.dev/eas/environment-variables/> and <https://docs.expo.dev/build-reference/apk/>.

## Common errors

- `ECONNREFUSED 127.0.0.1:27017`: the private local `.env` still points to local MongoDB. Run `npm run configure:local` and paste the completed Atlas URI.
- Atlas authentication error: `<db_password>` was not replaced, the password needs URL encoding, or the database-user password is wrong.
- Atlas server-selection error: check the Atlas IP access list and use `0.0.0.0/0` for this simple Vercel/changing-Wi-Fi setup.
- S3 403: verify all four values, exact bucket name/region, the attached `TekBooksS3Only` policy, and device time.
- `/ready` storage failure: the IAM user usually lacks `s3:ListBucket`, or the region/bucket is wrong.
- Resend test-mode error: `onboarding@resend.dev` sends only to `RESEND_TEST_RECIPIENT`. Use the Resend account email, or verify a domain and disable test mode.
- Local phone cannot connect: restart `npm run dev` after changing Wi-Fi, allow Node through Windows Firewall, or use `npm run dev:tunnel`.
- Installed APK calls a private IP: correct the EAS `EXPO_PUBLIC_API_URL` and rebuild the APK.
